# amazon-niche-sourcing

> 亚马逊「大类目 → 细分小类目 → 候选产品」选品流水线。
> 给一个大类目和一个站点，自动下钻细分、打分排序，每个细分产出 20 个候选产品（含参考 ASIN/链接、建议价、FBA、采购价、毛利率和可行性分析），最后生成一张可直接交给开发团队的 Excel 选品表。

适用于**精品铺货 / 精铺**团队：按类目批量出选品清单，而不是一个一个 ASIN 地手工翻。

---

## 它解决什么问题

传统做法是「打开卖家精灵 → 找类目 → 翻 Top100 → 看价格/评论 → 手动记表」，一个类目一天。

这个 skill 把整条链路脚本化：

```
大类目 + 站点
   │
   ├─ ① product_node 下钻 → 子类目列表
   ├─ ② 每个子类目 product_research Top100 → 四维打分（需求 / 竞争 / 价格带 / 评论壁垒）
   ├─ ③ 取前 N 个细分 → 抽规格矩阵（件数 × 颜色 × 材质 × 安装方式）→ 找供给缺口 → 20 个候选
   └─ ④ 渲染 Excel：细分总览 / 候选明细 / 细分结论 / 说明
```

---

## 候选是怎么选出来的

脚本不是随机挑商品，而是把每个细分的 Top100 商品标题抽成**规格维度**，再按「需求 ÷ 供给」找缺口：

| 类型 | 判定逻辑 | 例子 |
|---|---|---|
| **规格组合** | 某件数有销量、某颜色只有 0–2 个在售 → 缺口 | 20 件装月销 2,900 件，但金色仅 1 个在售 |
| **材质错位** | 某材质占比 ≤12%，做替换 | 全网 90% 塑料，上金属件 |
| **安装方式错位** | 免钉 / 卡扣 / 粘贴等安装方式稀缺 | 无钻孔方案供给不足 |
| **延伸款** | 加量装 / 套装 / 升级 / 小包装 / 礼盒 | 前 3 类不足 20 个时补齐，保证每个候选都有对标 ASIN |

每个候选都会挂 2–3 个**对标在售 ASIN**（可点击的 Amazon 链接），并附对标销量/评论、建议售价、FBA 费用、采购价估算、毛利率。

> ⚠️ 「20 个候选」里真正硬的规格缺口通常只有 5–8 个，其余是延伸款补齐。表格里用 🔴优先 / 🟡备选 / 🟢观察 标注，不要当成 20 个同等机会。

## 快速开始

### 1. 准备 key

需要一个可用的 [卖家精灵 MCP](https://www.sellersprite.com) key，两种方式二选一：

```bash
export SELLERSPRITE_KEY="你的key"
```

或在工作区放一个 `.mcp.json`：

```json
{
  "mcpServers": {
    "sellersprite": {
      "url": "https://mcp.sellersprite.com/mcp",
      "headers": { "secret-key": "你的key" }
    }
  }
}
```

### 2. 一键跑

```bash
python3 scripts/run.py \
  --site DE \
  --category "Insektenschutz" \
  --subs 5 \
  --per-sub 20 \
  --out 选品表_DE_防蚊纱窗_20261111.xlsx \
  --cn "防蚊纱窗" \
  --images
```

也可以分步跑：

```bash
# ① 大类目 → 细分
python3 scripts/scan.py --site DE --category "Insektenschutz" --top 5

# ② 单个细分 → 20 候选
python3 scripts/candidates.py --site DE --node "64187031:2860338031:2860457031" --name "防蚊纱窗" --n 20

# ③ 渲染表格
python3 scripts/workbook.py --out 选品表.xlsx --site DE --cn "防蚊纱窗"
```

### 3. 离线自测（不消耗接口额度）

```bash
python3 scripts/run.py --fake --subs 2 --out test.xlsx
```

## 输出的 Excel

| Sheet | 内容 |
|---|---|
| `细分总览` | 每个细分小类目的商品数、月销、月销额、均价、CR3、评论中位数、机会分 |
| `候选明细` | 每个候选：参考链接 1–3、类目排名/销量、售价、FBA、采购价、毛利率、尺寸、可行性分析 |
| `细分结论` | 每个细分的结论（强推 / 可做 / 观察）与建议动作 |
| `说明` | 数据口径、公式、抓取限制 |

`候选明细` 的列结构与常见的精铺开发表对齐：

```
开发｜站点｜sku｜参考链接1-3｜类目排名/销量｜采购商｜采购商链接(1688)｜图片
｜产品名称参数｜关键词｜售价｜FBA费用｜采购价｜毛利率｜备注｜长｜宽｜高｜机会分｜可行性分析｜细分小类目
```

## 评分口径

**细分机会分 = 四维各 0–5 分，满分 20**

| 维度 | 规则 |
|---|---|
| 需求 | 月销额 >€150k 得 5 分，<€15k 得 1 分 |
| 竞争空间 | CR3 <30% 得 5 分，>65% 得 1 分 |
| 价格带 | 均价 €10–25 得 5 分（适配 FBA 和毛利） |
| 评论壁垒 | 评论中位数 <50 条得 5 分 |

**毛利率**

```
毛利率 = (售价/1.19 - 售价/1.19×15% - FBA - 采购价/7.8) / (售价/1.19)
```

汇率按 7.8，佣金 15%，VAT 19%。

## 已知限制

- **没有 1688 数据接口**：采购链接是按中文关键词生成的搜索链接，采购商和采购价需要自己询价（脚本按售价 22% 估算采购价）
- **FBA 费用是估算**（`1.9 + 0.22×√售价`），上架前必须用亚马逊费用计算器复核
- **卖家精灵是总量配额**，用尽会返回 `ERROR_VISIT_MAX`；`mcp_client.py` 有 1 小时磁盘缓存和缓存回退
- **类目节点各站点独立**，DE 的节点 ID 不能拿到 UK 用
- 销量/评论均为估算值，只用于相对比较，不能当财务报表
